# Tworzenie migracji Flyway

Utwórz nową migrację SQL dla PostgreSQL zgodnie z konwencjami projektu.

## Krok 1 — Ustalenie numeru wersji

```bash
ls trener-ai-app/src/main/resources/db/migration/
```

Znajdź najwyższy numer wersji (V1, V2, ...) i użyj kolejnego.

## Krok 2 — Utworzenie pliku migracji

Nazwa pliku: `V{N}__{opis_snake_case}.sql` (dwa podkreślniki po numerze wersji).

Ścieżka: `trener-ai-app/src/main/resources/db/migration/`

## Krok 3 — Napisanie SQL

Na podstawie argumentu `$ARGUMENTS` napisz migrację SQL. Zasady:
- Dialekt PostgreSQL 17
- `bigint GENERATED BY DEFAULT AS IDENTITY` dla kluczy głównych
- `timestamp(6) with time zone` dla dat z czasem
- Klucze obce z `REFERENCES tabela(id)`
- Nazwy tabel i kolumn w snake_case
- Kolumny NOT NULL tam, gdzie to sensowne
- Dodaj komentarz na początku pliku z opisem zmian

## Krok 4 — Weryfikacja

```bash
cd trener-ai-app && mvn compile -B
```

Hibernate z `ddl-auto: validate` zweryfikuje, czy migracja jest spójna z encjami JPA. Jeśli nie — popraw migrację lub encję.

## Krok 5 — Przypomnienie

Wyświetl użytkownikowi:
- Ścieżkę utworzonego pliku
- Treść migracji
- Przypomnienie: jeśli migracja wymaga nowej encji JPA lub zmian w istniejącej, opisz jakie zmiany są potrzebne w `model/`.
